# Native paid inference: decision record and acceptance fixtures (P1, X2)

Version 1, 2026-09-21. Supersedes the open questions of "ARC Chain V2:
inference and release contract, draft 1" (2026-09-19) for what is now
implemented. Every decision names its implementation and the test that
accepts it. "Executed" means the test ran and passed on this branch; a
fixture that exists but has not run in an integrated setting says so.

Scope: private protocol-4 native inference on a fresh genesis. It does not
activate anything on the recovered protocol-3 network.

| D20 | Commit-time selection skips a candidate whose nonce its sender has already used WITHOUT counting it toward the 64-candidate cap, so the selected transaction does not depend on which receipts a node holds (a node rebased onto a checkpoint holds none below it). **Activation is explicit and per chain:** the rule is part of the native activation record and its commitment (`NativeSelectionRule`). Chains activated before D20 decode as `count-every-candidate-v1` and keep the original record bytes, commitment and counting rule, so an upgraded binary selects exactly as the binaries beside it. New activations record `skip-used-nonces-v2` (operator config `selection_rule`, default v2). **Mixed versions:** the fail-closed guarantee covers a chain that is ALREADY activated v2 - a binary without D20 decodes activation records exactly, refuses the v2 record it finds in state, and stops at open rather than running that chain under the old rule. It does NOT cover first activation: the activation row is never gossiped, every node is started with its own `--native-inference-activation` config, and a pre-D20 binary handed a v2 config ignores the `selection_rule` field it does not know, writes a legacy record and commits `commitment_v1` while its D20 peers commit `commitment_v2` - a genesis-height state-root fork, not a refusal. `NativeActivationRequest` now carries `#[serde(deny_unknown_fields)]` so the NEXT such field fails closed on an older binary, which does nothing for binaries already built: rolling a new activation config to a mixed fleet is an operational sequencing requirement, not something the format enforces. No in-place migration: moving an existing chain to v2 needs a new activation. Checkpoint adoption (C11) requires v2. | `select_native_block_transactions`, `encode_activation`/`decode_activation`, `InferenceAdmissionContext::commitment` in `arc-state::inference_contract_state`; `NativeActivationRequest::selection_rule` in `arc-node::native_inference` | `already_used_nonces_do_not_consume_the_candidate_cap`, `a_rule_v1_chain_keeps_counting_used_nonces`, `each_selection_rule_has_one_activation_layout_and_its_own_commitment`, `a_rule_v1_chain_never_adopts_a_checkpoint`, `selection_examines_a_bounded_number_of_candidates_per_block` | implemented and merged (41c25c59); named tests pass |
| D21 | A chain's certificate domain binds the chain RUN, not just its genesis: `[chain] instance_id` in the genesis file is committed by `network_hash`, which is the `ConsensusDomain` hash every finality certificate, recovery decision and checkpoint envelope is signed under. Two runs of the same genesis file with the same committee - a reset devnet, a re-run fixture, a restored-from-scratch chain - are therefore different domains, and a certificate or checkpoint payload from one cannot verify on the other. **Backward compatible:** absent, the network hash is byte-identical to the hash the same file produced before the field existed, so a running chain keeps its identity and needs no restart; the field is a tagged suffix, not a v3-body change. Disposable chains (local dev, the multiprocess fixtures, the soak harness) generate a fresh id per run, which is where the same genesis is otherwise reused verbatim. A production chain sets it once at genesis and never changes it - changing it is a new chain. | `ChainInfo::instance_id`, `GenesisConfig::canonical_network_hash` in `arc-node::config` | `network_hash_separates_runs_of_the_same_genesis`, `an_adopted_window_must_extend_this_node_s_own_chain` (arc-state) | executed |

## Compatibility matrix

| Surface | Behaviour preserved | Status |
|---|---|---|
| Protocol-3 paid ingress | disabled; no alternative ingress bypasses it | D1, D12 executed |
| Free / sharded HTTP inference | execution evidence only, never a receipt | D1 executed |
| Protocol-4 transactions on an older binary | an older node cannot decode `NativeInferenceVote` (0x1B) or a WAL with `Rebase`; it refuses, never misreads | wire and WAL tags are new trailing variants |
| Snapshot v1 vs v2 | each side refuses the other's snapshot and replays the full WAL | `a_snapshot_from_an_unknown_version_is_ignored_not_guessed_at` executed |
| Explorer / apps | native receipts shown only from the canonical receipt; reconciliation and replica agreement explicit | local-dev view (U2/P9); production explorer unchanged |
| Real-model execution | behind artifact qualification (M4) - the deterministic test executor qualifies nothing | open |
