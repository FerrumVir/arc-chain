# Batch 3 StateDB/WAL seam proposal

Inspection was limited to `crates/arc-state/src/lib.rs` and `wal.rs`; no state or WAL edits were made.

`StateDB` owns canonical account balances, storage, receipts, and replay (`lib.rs:562-666`, `1272-1338`). Existing mutators write DashMaps before queuing independent `WalOp::SetAccount`/`SetStorage` records (`lib.rs:1637-1647`, `lib.rs:7500-7560`), so composing those public methods cannot provide atomic escrow settlement. `WalWriter::append` is intentionally non-blocking and returns no result (`wal.rs:1024-1073`); only `sync` reports the durable barrier (`wal.rs:1075+`). A failed append must therefore make the writer unhealthy and prevent acknowledgement.

The smallest safe seam is an isolated `StateDB` adapter with private ownership of the state handle and a serialized transition method. Its constructor should reject recovery-bound/live activation contexts until a future protocol gate exists. Admission, finalize, and refund should validate against the existing pure contract, trusted state domain/member snapshot, account balance/nonce, and registered model/profile/assignment context before building one bounded typed transition record. The record should contain complete replacement account snapshots, escrow/request metadata, terminal receipt/output metadata, and a consumed pending marker. Store the request/terminal commitment and bounded output in the escrow account/storage state so the existing recovery state root commits them (`recovery.rs:2485-2535`).

Add one new `WalOp` variant at the end of the enum (`wal.rs:509-560`) to preserve historical bincode discriminants. Append that one record, then the existing checkpoint boundary, and fsync before publishing the in-memory transition. Replay `apply_wal_op` must apply the typed record as one semantic unit (`lib.rs:1272-1338`). If append/sync fails or acknowledgement is uncertain, return an error, latch unavailable/reopen-required state, and never acknowledge; do not attempt rollback through separate WAL writes. The adapter must serialize transitions (`&mut self` or a private mutex) and expose no raw mutation methods, since globally locking `StateDB` would race existing hot-chain mutators.

Restart tests should cover durable admission, finalize, refund, torn/uncheckpointed tail, replay idempotence, duplicate terminal rejection, conservation, and failure-before-ack. Existing protocol-v3 transaction families remain untouched and disabled. This seam still requires a future activation/state integration review; it does not make native paid inference live.
